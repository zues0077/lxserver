## 一、汽水音乐：扫码登录后 lx-music「没变化」

**现象**：在后台「平台账号 → 汽水」用手机扫码，手机显示已登录，但 lx-music 客户端还是没登录上、取不到歌。

**原因**：新设备 / 异地登录会触发汽水的 `account_flow=verify`（短信二次验证，`error_code=2046`）。当前版本的网页二维码流程只实现了 web-passport 二维码，**没有实现这个二次验证分支** → 手机端把登录接管进汽水 App，网页 token 永远拿不到 `sessionid/sid_tt`，所以 lx-music 侧「登录没变化」。

**解决（绕过）**：
- 用「填写 Cookie」方式登录（把汽水网页版登录后的 Cookie 粘进来）；或
- 用弹窗里的「下载扩展包」装好浏览器扩展，点「一键同步」。

> 这跟「播整曲 / 无损」是两件事：扫码登录是取**账号**，签名器是给**已登录账号**的歌曲签名，两者互不影响。

## 二、汽水签名器怎么用 / 为什么需要它

**是什么**：`tools/qishui-signer/`（Windows 侧程序，默认监听 `http://localhost:18080/`）。汽水整曲 / 无损播放需要字节官方安全组件（`bdms.node` + `metasecml.dll`）签名，这个组件只在**装有汽水客户端的 Windows** 上才有（`app.asar.unpacked`），Docker 容器里没有 → 所以签名器必须跑在有汽水客户端的 Windows 上，不在镜像内。

**作用范围**：**只影响「播整曲 / 无损」**，与登录无关。想离线听就「缓存到服务器」。

**网页配置页**（v1.5.34+）：浏览器打开 `http://localhost:18080/` 即看到表单，可设端口 / 绑定地址 / LX 服务器列表；保存**热生效**（改端口热重启监听、服务器列表立即重新登记），配置落 `config.json`。

**多服务器安全**：签名器**无状态**（汽水账号态在各 LX 服务器里），同一签名器可同时给多台 LX 登记 / 签名，**互不影响汽水账号** → 后台「汽水签名器」填的是签名器地址，可填多台。

## 三、后台「如何获取」弹窗关不掉

**现象**：点「平台账号 → 汽水 → 如何获取」，弹出的说明弹窗关不掉。

**原因**：源码关闭逻辑本身正确（关闭按钮置 `display:none`），关不掉几乎都是**浏览器缓存了旧的 app.js**。

**解决**：硬刷新（Windows `Ctrl+Shift+R` / Mac `Cmd+Shift+R`）即可。想更稳可后续补 Esc / 点遮罩关闭。

## 四、下载的文件落在哪？cache 和 music 有什么区别

**播放即缓存（默认开）**：解析到在线 URL 后自动把**完整音频**写入 **cache**，不阻塞播放。注意这个调用**不传** `enableOnlyDownloadMode`，所以播放缓存永远落 cache。

**手动下载**走下载队列，传 `enableOnlyDownloadMode`（前端默认 `true`）→ **默认直接写 music**；关掉该开关才写 cache，之后靠「移动目录」转过去。

**真实入口**：
- 右键单曲「下载到服务器 / 缓存到服务器」——文案随 `enableOnlyDownloadMode` 变，目标音质已在 cache 时会**自动移过去**；
- 本地音乐页勾选文件 → 橙色「移动目录」按钮（cache ↔ music 双向），music 下带子目录 / 分类的歌不能移入 cache；
- 同栏蓝色「云端同步」不是这个，它切 `serverCacheLocation`（root ↔ data）。

**落点唯一判据**：`fileCache.ts` 的 `ensureDir(username, isOnlyDownload)`（`true→music`，`false→cache`）。cache 已有文件时**复制**到 music 而非重下。

## 五、开了「容量清理」为什么会删掉我已下载的歌

默认 `user.enableCacheSizeLimit=false`（不清理）。一旦开启，每次下载完检查，统计口径 = **cache + music 合计**（只算 mp3/flac/m4a/ogg/wav/lrc），超限按 mtime 从旧到新删到 95%，**cache 与 music 一起删**（会删已下载的歌）。若只想保留下载目录，请勿开启容量清理，或把 music 放到独立存储。

## 六、cover_cache 为什么必须单独挂载

`cover_cache` 的路径是 `process.cwd()` 下的特例，恒用 `/server/cover_cache`，**不受 `serverCacheLocation` 影响**。切 data 模式也照样写 `/server/cover_cache` → 必须单独挂载，否则封面写进容器可写层，重启即丢。所有容器务必挂 `data + cache + music + cover_cache` 四项。

## 七、音质标称和实际不一致

落盘前用 `file-type` + `inspectAudioFile` **实测**纠正音质，是**实测值不是请求值**。命名默认 `simple` = `歌名 - 歌手 - 音质 - 专辑`；`standard` 带 source+id；>200 字符截断、非法字符换 `_`。

## 八、小爱音箱投播没声音 / 搜不到

前提：小爱音箱与 lxserver 在同一局域网，且已在后台开启 XiaoAi 投播并绑定账号。常见卡点：
- 音箱固件过旧不支持；
- lxserver 未开放对应端口（检查防火墙 / 反代）；
- 账号未绑定或绑定失效，重新在后台绑定一次。

## 九、镜像版本和代码版本对不上

GHCR 镜像可能因 `[skip ci]` 提交被跳过而**落后于代码**（例如代码已到 v1.5.34 但线上镜像停在 v1.5.32）。`/health` 返回的版本以代码为准；要更新线上需发一次不含 `[skip ci]` 的推送（或手动 ghcr 构建）。

## 十、平台账号是独立视图吗

是的。后台「平台账号」是独立导航视图，支持网易 / QQ / 微信 / 酷狗 / **汽水** / **B站** 扫码或填 Cookie 登录取链，与「我的音乐 / 同步」分开管理。
